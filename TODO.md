# TODO — мультисерверная генерация конфигов

Переход от одного VPN-сервера к четырём с разными панелями.

## Целевая картина

Один получатель — одно клиентское имя — четыре артефакта:

| Сервер | Панель | Транспорт | Артефакт |
|---|---|---|---|
| `ru` | WireGuard Easy v15 | ssh | файл `.conf` |
| `de2` | AmneziaWG Web UI | ssh | файл `.conf` |
| `de` | 3x-ui | direct | ссылка подписки |
| `ru2` | 3x-ui | direct | ссылка подписки |

В письмо уходят **2 файла вложениями + 2 ссылки подписки в теле**.

Решения, принятые до начала работы:
- Транспорт (`ssh` / `direct`) задаётся у каждого сервера в конфиге, не глобально.
- Версия 3x-ui определяется в рантайме: пробуем новый `/panel/api/clients/add`,
  при 404 откатываемся на старый `/panel/api/inbounds/addClient`.
- wg-easy — v15 (Basic Auth), v14 не поддерживаем.

## 9. Несколько конфигов у одного получателя — сделано

Возврат возможности, снятой на этапе 5. Формат вставки: `имя<TAB>почта<TAB>количество`,
третья колонка необязательная (нет → 1). Имена всегда с номером через дефис:
`alice-1`, `alice-2`. Количество — «сколько должно стать»: повторный импорт ничего
не меняет, уменьшение игнорируется.

## 12. Перед боевым прогоном

Всё, что до сих пор исполнялось только на заглушках и макетах. Список пережил
несколько тестовых кампаний; пункты про них выброшены, осталось только то, что
относится к боевому прогону.

Сделано и проверено на живых серверах:

- [x] `servers.yml` с боевыми доступами; `make check_servers` — отвечают все четыре
      панели: `ru` (wg-easy), `ru2` и `de` (3x-ui), `de2` (AmneziaWG).
- [x] `make check_smtp` — вход на `smtp.gmail.com:587` проходит.
- [x] `make check_bindings` — сверка привязок с живыми панелями.
- [x] Адоптация проверена на **всех** типах панелей: `ru` (клиенты, заведённые вручную),
      `de` (пять клиентов, заведённых на панели вручную),
      `de2` и `ru2` — то же самое. Программа забирает
      существующего клиента, а не создаёт второго.
- [x] Ссылки подписки собираются верно на обоих 3x-ui: база берётся из настроек

      клиента в ссылку идёт его `subId`, а не имя.
- [x] Письмо: тело в quoted-printable (иначе клиенты склеивали строки со ссылками),

- [x] Повтор упавших писем: воркер берёт только PENDING, поэтому после завершения
      кампании упавший получатель оставался без конфигов навсегда. Кнопка «Повторить
      неотправленные (N)» возвращает их в очередь и открывает кампанию для запуска,
      не трогая отправленных.

- [x] Аудит безопасности. История git чиста — `servers.yml`, `.env` и база в неё
      никогда не попадали. Закрыто: `.gitignore` расширен на файлы-варианты
