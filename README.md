# vibe_mail

HTTP-API сервис для массовой рассылки писем. Клиент (админка `admin-front`)
создаёт кампании, добавляет получателей, запускает рассылку; отправка идёт
в фоне, а прогресс виден по статусам в БД.

Стек: **FastAPI** + **Uvicorn**, **SQLAlchemy 2.x** + **SQLite**, **Pydantic**,
менеджер зависимостей — **Pipenv**.

## Быстрый старт

```bash
pip install pipenv                                  # если ещё не стоит
PIPENV_VENV_IN_PROJECT=1 pipenv install             # создаёт .venv и ставит зависимости
cp .env.example .env                                # и заполни SMTP_PASSWORD
make dev                                            # или: pipenv run python -m app
```

После запуска:
- API доступно на `http://127.0.0.1:8000`
- интерактивная документация Swagger — `http://127.0.0.1:8000/docs`

Остановка: `Ctrl+C`.

Альтернативный запуск напрямую через интерпретатор виртуалки:

```bash
pipenv run python -m app --reload --port 8000
```

## Конфигурация (`.env`)

| Переменная | Назначение | По умолчанию |
|---|---|---|
| `SMTP_HOST` | хост SMTP-сервера | `smtp.gmail.com` |
| `SMTP_PORT` | порт (465 — SSL, 587 — STARTTLS) | `587` |
| `SMTP_USER` | логин отправителя | — |
| `SMTP_PASSWORD` | пароль приложения (не основной!) | — |
| `SMTP_USE_TLS` | STARTTLS для порта 587 | `true` |
| `SMTP_USE_SSL` | SSL для порта 465 | `false` |
| `DATABASE_URL` | путь к SQLite | `sqlite:///./vibe_mail.db` |

Для Gmail/Яндекса нужен **пароль приложения**, а не основной пароль аккаунта.

## API

Базовый префикс: `/api`.

| Метод | Путь | Назначение |
|---|---|---|
| `GET` | `/api/health` | проверка здоровья |
| `POST` | `/api/campaigns` | создать кампанию |
| `GET` | `/api/campaigns` | список кампаний + прогресс |
| `GET` | `/api/campaigns/{id}` | кампания + счётчики |
| `POST` | `/api/campaigns/{id}/recipients` | добавить получателей (`{"items": [...]}`), атомарно |
| `GET` | `/api/campaigns/{id}/recipients` | список получателей |
| `POST` | `/api/campaigns/{id}/recipients/preview` | предпросмотр вставленного списка, ничего не пишет |
| `POST` | `/api/campaigns/{id}/recipients/import` | импорт вставленного списка |
| `POST` | `/api/campaigns/{id}/start` | запустить рассылку (202, воркер отправляет в фоне) |
| `POST` | `/api/campaigns/{id}/stop` | приостановить рассылку |
| `DELETE` | `/api/recipients/{rid}` | удалить получателя |

Пример создания кампании и запуска:

```bash
curl -X POST http://127.0.0.1:8000/api/campaigns \
  -H 'Content-Type: application/json' \
  -d '{"name":"Рассылка","subject":"Привет","body":"Текст письма"}'

curl -X POST http://127.0.0.1:8000/api/campaigns/1/recipients \
  -H 'Content-Type: application/json' \
  -d '{"items":[{"email":"a@b.c"},{"email":"x@y.z"}]}'

curl -X POST http://127.0.0.1:8000/api/campaigns/1/start
```

Импорт списка из таблицы (две колонки через таб — имя конфига и почта):

```bash
curl -X POST http://127.0.0.1:8000/api/campaigns/1/recipients/import \
  -H 'Content-Type: application/json' \
  --data-binary $'{"text":"Plus_Vibe\tplusvibe@slop.com\nPlus_Vibe_2\tplusvibe@slop.com"}'
```

## Как это работает

- **Получатели и конфиги.** Список вставляется как две колонки из таблицы (имя конфига
  и почта, разделитель — таб). Строки с одинаковой почтой объединяются в одно письмо с
  несколькими конфигами. Сначала `preview` показывает, что получится, потом `import`
  сохраняет: валидные строки создаются, проблемные возвращаются списком с номером строки.
  Имена конфигов уезжают в тело письма столбиком под текстом кампании.
- **Валидация до отправки.** Адреса проверяются при добавлении получателей
  (синтаксис, дубликаты в рамках кампании), а при `start` — готовность кампании.
  При любой проблеме — `400` со списком, старт не происходит.
- **Возобновление.** Статусы получателей (`pending`/`sent`/`failed`) хранятся в БД.
  При перезапуске процесса «зависшие» запущенные кампании подхватываются воркером
  автоматически.
- **Ретраи.** Временные ошибки (4xx, обрыв, таймаут) — до 3 попыток с паузой
  2/4/8 с и переподключением. Постоянные (5xx, отказ получателя/отправителя) —
  получатель помечается `failed`, рассылка продолжается.
- **Фоновая отправка.** Запрос `start` возвращает `202`; реальную отправку делает
  отдельный поток (`app/services/worker.py`), запущенный при старте приложения.
  Это не блокирует HTTP-запрос и позволяет фронту опрашивать прогресс.

## Заметки

- Легаси-CLI (`send_mail.py`, `import_csv.py`, `config.example.yaml`) удалён вместе

  отдельной итерацией.
- `.vscode/` не коммитится (настройки редактора в `.gitignore`).
